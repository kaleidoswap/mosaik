Mosaik

A DEX on Liquid where every order is a Tessera — a self-enforcing Simplicity covenant. A market is a mosaic of tesserae.
📅 16–17 May 2026 · 10:00–18:00 👥 3 developers 🦀 Rust workspace + SimplicityHL 🌊 Liquid / Elements regtest

The pitch

A maker locks asset A into a single Liquid UTXO controlled by a Simplicity covenant. The covenant inspects any transaction that tries to spend the coin and permits it only if the maker is paid exactly the agreed amount of asset B. That one UTXO is the offer: permissionless to fill, uncheatable, atomic — no order book, no maker server, no counterparty trust.

Why it needs Simplicity. The construction rests on transaction introspection — a coin reading the outputs of the transaction spending it. Bitcoin Script cannot do this. LiquiDEX-style swaps get atomicity from a SIGHASH trick; adaptor-signature PTLCs work on plain Taproot. A covenant that enforces the counter-payment is the thing that genuinely requires Simplicity.

How it works

Covenant UTXO (holds amount_A of asset A) ├─ SETTLE spendable by ANYONE iff the spending tx pays │ exactly amount_B of asset B to the MAKER └─ REFUND after TIMEOUT, spendable by the MAKER's signature maker ──1. lock asset A in the covenant UTXO──▶ publish outpoint taker ──2. build tx: covenant UTXO + own coins in; amount_B → maker, amount_A → taker, + fee──▶ broadcast ──3. covenant verifies the maker's output, or the tx is invalid

Offer terms (asset B, amount B, maker script, timeout, maker key) are committed into the Taproot tapleaf — immutable once the offer exists. Full spec in docs/DESIGN.md.

Team — three tracks, one workspace

Each dev owns one crate. The crate boundaries that already exist in the repo are the integration contracts, so the three tracks run in parallel from hour one.

  • Implement & test the SETTLE path (output asset/amount/script)
