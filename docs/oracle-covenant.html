Mosaik · Tessera covenant

The oracle-settled covenant

A maker stops posting a price and starts posting a rule. The order tracks the market until it is filled or reclaimed — priced off-chain, enforced by a Simplicity covenant, with no clock anywhere on-chain.

What Mosaik ships today. Phase 1 implements the maker-signed quote covenant — the RFQ variant in §3. The covenant is price-less; the maker signs a per-fill quote and the covenant verifies the maker's own BIP-340 signature. There is no oracle inside the covenant: it trusts only the maker, whose funds are locked. The oracle-signed design below is a future option for fully-offline makers. And note the honest framing — an oracle or quote covenant does not eliminate the free option, it bounds it to block-time latency; the maker prices that bounded option with a spread.

01 Two ways to price an order

A fixed-price covenant is a free option written to the whole market: if the price moves, the maker is picked off. An oracle-settled covenant settles at the market rate, so there is no stale quote to exploit.

Fixed price — today

"0.01 L-BTC for exactly 50 USDT"

The amount is frozen into the covenant tapleaf at funding time.

  • Simple — the covenant just checks one output.
  • No external dependency.
  • Free option: a stale order is filled the moment the market moves through it.
  • The maker must babysit and re-post.
Oracle settled

"0.01 L-BTC at oracle mid + 0.2%"

The covenant bakes a rule: oracle key, pair, spread.

  • Settles at the live market rate — no free option.
  • Fund once, leave it; it tracks the market.
  • Reuses jet::bip_0340_verify — already proven on-chain by the REFUND path.
  • Liveness now depends on the oracle.

02 How blocks work — freshness without a clock

A Simplicity covenant cannot ask "what block is it now." It only sees the spending transaction. So freshness rides on block height: the oracle attests a height, and the covenant sandwiches the transaction's nLockTime against it.

oracle signs   ( pair ‖ price ‖ attested_H )

covenant requires   attested_H  ≤  tx.nLockTime  ≤  attested_H + N
consensus enforces               tx.nLockTime  ≤  chain tip
─────────────────────────────────────────────
⇒ the attestation is provably no more than N blocks old

The covenant never needs wall-clock time — only the transaction's own locktime and a comparison. The same primitive the REFUND path already uses (check_lock_height) does the freshness check.

Too old an attestation → the covenant rejects it as stale. Too new an nLockTime → consensus rejects the tx as non-final. The taker must land inside the band — and the band is exactly the window the maker priced for.

External dependencynone oracle must be livenone
Capital efficiencyone fill, then dead one fill, then dead fund once, many fills

The window N is the dial. Small N → tight pricing, but the taker must act fast and the oracle must attest often. Large N → the taker gets a bigger timing option, so the maker's spread s must cover N blocks of volatility. The spread is the maker's premium for granting an N-block option — not just margin.
